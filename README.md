Encontros que Transformam — Deploy seguro com Vercel + Supabase
===============================================

Resumo
------
Este projeto contém um frontend estático e uma Serverless Function para receber cadastros
com segurança usando a `SUPABASE_SERVICE_ROLE_KEY` (armazenada como variável de ambiente no Vercel).

Arquivos importantes
- `site/contato.html` — formulário frontend
- `script.js` — comportamento do menu e envio do formulário para `/api/cadastro`
- `api/cadastro.js` — função serverless (Vercel) que grava no Supabase usando a service role key

Configurar Supabase
-------------------
1. No painel Supabase, crie a tabela `cadastros` (SQL sugerido):

```sql
create table public.cadastros (
  id bigint generated by default as identity primary key,
  nome text not null,
  email text not null,
  telefone text,
  cidade text,
  escolaridade text,
  mensagem text,
  created_at timestamptz default now()
);
alter table public.cadastros enable row level security;
create policy "Allow anon inserts" on public.cadastros
  for insert using (auth.role() = 'anon')
  with check (auth.role() = 'anon');
```

2. (Opcional) Ajuste RLS se quiser que apenas a API (service_role) escreva.

Variáveis de ambiente (Vercel)
------------------------------
No painel do projeto Vercel, defina estas variáveis:

- `SUPABASE_URL` — URL do seu projeto Supabase (ex: `https://xyzcompany.supabase.co`)
- `SUPABASE_SERVICE_ROLE_KEY` — service role key (mantenha privada)

Passos para deploy no Vercel
---------------------------
1. Commit e push do repositório para GitHub.
2. Conecte o repositório ao Vercel (você pode usar o botão Import Project).
3. No painel do projeto, adicione as variáveis de ambiente mencionadas acima.
4. Deploy. A função `api/cadastro` será publicada automaticamente.

Testar localmente
-----------------
Instale o Vercel CLI e rode em modo dev:

```bash
npm i -g vercel
vercel login
vercel dev
# abra http://localhost:3000/site/contato.html
```

Observações de segurança
-----------------------
- Nunca publique a `SUPABASE_SERVICE_ROLE_KEY` no frontend. Use a Serverless Function (como `api/cadastro`) para operações confiáveis e seguras.
- Para um fluxo sem backend, você pode usar a `anon` key diretamente no frontend, mas isso expõe permissões — não recomendado para produção sensível.
